# CHARLES.MARKET

A play-money prediction console built on **one chaotic friend named
Charles**. Trade Yes/No tickets in shekels (₪) on his next mishap,
milestone, or antic. Anyone can propose a ticket; admins approve, create,
edit, close, resolve, and delete.

The git repo / package name stays `charlesmarket` (one word) for code and
deploys. Every user-facing string says `CHARLES.MARKET` and refers to
each row as a **ticket**, not a market. The word "market" survives only
in Convex code identifiers (`api.markets.list`, `Id<"markets">`).

## Stack

- **TanStack Start** (`@tanstack/react-start` + `@tanstack/react-router`)
  on Vite + Nitro for SSR.
- **React 19** with the React Compiler enabled.
- **Tailwind v4** + **shadcn/ui** primitives in `src/components/ui/*`.
  Re-add via `pnpm dlx shadcn@latest add <component>` and then restyle
  to the console tokens (see DESIGN.md).
- **Convex** for the backend (database + queries/mutations + realtime).
- **Convex Auth** with **Google OAuth** for sign-in.
- **Sonner** for toasts, **Lucide** icons, **Biome** for format + lint.
- **Funnel Display / Funnel Sans** + **JetBrains Mono** loaded from
  Google Fonts. No Inter, no NVIDIA green — see DESIGN.md.

## Key conventions

### Reading data on the client

Always go through Convex hooks, not module-level imports:

```tsx
import { useQuery } from "convex/react";
import { api } from "../../convex/_generated/api";

const tickets = useQuery(api.markets.list, { category: "All" });
// tickets === undefined while loading
```

Map Convex docs to the UI shape with `toUIMarket(doc, history?)` from
`src/lib/markets.ts` — adds `closesIn`, `delta`, `trend`. UI components
type against `UIMarket`, not the raw Convex `Doc<"markets">`.

### Auth

- **Server**: `await requireUser(ctx)` (throws if unauthenticated),
  `await currentUser(ctx)` (returns `null`), or `await requireAdmin(ctx)`
  (throws unless `user.isAdmin === true`). All imported from `./users`.
- **Client**: `useConvexAuth()` for `{ isAuthenticated, isLoading }`, or
  the `<Authenticated>` / `<Unauthenticated>` / `<AuthLoading>` switch
  components from `convex/react`.
- **Trading gate**: every mutation that places an order, posts a
  comment, submits a proposal, or touches admin tools requires auth on
  the server. The UI mirrors this — `OrderTicket`, `/propose`, and the
  mobile sticky CTA render a sign-in panel when unauthenticated, never a
  disabled button.
- **Admin gate**: `isAdminUser(user)` is just `Boolean(user?.isAdmin)`.
  No env-var allowlist — admin status lives in the DB. Bootstrap the
  first admin once with
  `npx convex run admin:bootstrapAdmin '{"email":"..."}'` (refuses to
  run if any admin already exists). Subsequent admins are granted via
  `api.admin.grantAdmin` from the user drawer in `/admin/users`.

### Privacy

- **No email addresses on non-admin surfaces.** `users.me` returns the
  caller's own email (shown only to them — used nowhere). `publicProfile`
  intentionally omits email and `name`. The user-facing UserMenu does
  not display the email. Admin pages (`/admin/users`) still show emails
  for moderation.
- **No `display name` UI.** The `users.name` column exists (seeded from
  Google profile) but is only surfaced inside `/admin/users`. The
  `users.updateName` mutation has been removed.

### Currency

- **Symbol**: `CURRENCY_SYMBOL` (`₪`) from `@/lib/markets`. Don't hardcode.
- **Display**: always **whole shekels, no decimals**. Use `money(n)` for
  large amounts (returns `₪1.2k`, `₪34M`) or `Math.round(n)` + symbol
  for raw values. `cents(p)` renders the 0–1 probability as `₪78`.
- **Starting balance**: `STARTING_BALANCE = 1000`. Set by
  `createOrUpdateUser` callback on first sign-in.
- **Balance adjustments**: `api.admin.adjustBalance({ userId, setTo?, delta? })`
  is the admin-only way to change a user's cash. Surfaced in the
  `/admin/users` drawer. No public top-up.

### Ticket lifecycle

```
proposal (pending) ──approve──> ticket (open) ──close──> ticket (closed) ──resolve(Yes|No)──> ticket (resolved)
              └─reject──> stays in proposals with rejectionReason
```

- `proposals.approve` inserts a row in `markets` and seeds the first
  `priceTicks` entry, then links the proposal via `approvedMarketId`.
- `admin.resolveMarket` pays out winning positions (1 ₪/share), records
  closing trades, zeroes positions, sets `yesPrice` to 0 or 1, and writes
  a final priceTick.
- `admin.deleteMarket` cascades trades/positions/comments/priceTicks and
  unlinks proposals.

### Schema notes

- `markets` and `marketProposals` carry: `question`, optional free-text
  `description`, `category`, `tags`, `closesAt` (display label) +
  `closesAtMs` (numeric), `initialYesPrice`, `initialLiquidity`.
- `users` has a `by_handle` index (added when public profiles shipped).
  `handle` is `v.optional(v.string())` so the auth seed can write the row
  before `createOrUpdateUser` fills the rest.
- `resolutionSource` is **deprecated** — kept as `v.optional(v.string())`
  on both tables so existing rows pass validation, but no code writes it.
  Run `npx convex run migrations:stripResolutionSource` to drop it from
  every row, then remove the optional field from `schema.ts`.
- `users.isAdmin` is the only source of truth for admin status.

### Design system

Read **DESIGN.md** first if you're touching styles. Short version:

- Dark by default ("Console"). Light theme exists but inherits the same
  tokens.
- One brand color: chemical lime (`--brand`). The only other strong color
  is `--magenta` for No / loss / danger.
- Two families: **Funnel** (display + body) and **JetBrains Mono**
  (numerals, timestamps, status chips, market IDs).
- Sharp corners (2–4px). No drop shadows on cards (use 1px `--rule`
  borders). No gradient text. No glass blur.
- Custom Tailwind utility classes in `global.css`: `kicker`,
  `bracket-chip`, `price-slab`, `ledger-row`, `display-headline`,
  `display-question`, `mono-input`, `panel`, `bezel`, `spark-path`.
- Reusable helpers in `src/components/console.tsx`: `marketId(slug)` for
  the `M-007` ticker, `BracketChip`, `Kicker`, `Sparkline`, `Stat`.

### Routes & search params

TanStack file-based routing. To add a new route, drop a file in
`src/routes/`; the route tree regenerates on the next `pnpm dev`. Use
`validateSearch` for query-param-backed UI state (see `tickets.tsx`
for the canonical pattern).

When renaming a public URL, leave a stub at the old path that does
`throw redirect({ to: "..." })` so existing share links survive. See
`markets.tsx`, `market.$id.tsx`, and `admin/markets.tsx` for examples.

For pages that need both a layout and an index (`/profile` shows the
viewer's own profile *and* hosts `/profile/$username`), use the layout
pattern: `profile.tsx` is `<Outlet />`, `profile.index.tsx` is the
index, `profile.$username.tsx` is the child.

### Toasts

Always wrap mutations in try/catch and surface result via Sonner:

```tsx
try {
  const r = await placeOrder({ ... });
  toast.success("Bought Yes · ₪100", { description: `...` });
} catch (err) {
  toast.error("Order failed", {
    description: err instanceof Error ? err.message : String(err),
  });
}
```

## Deployment (Vercel + Convex)

- Build command on Vercel: `npx convex deploy --cmd 'pnpm run build'`
- Required env var on Vercel: `CONVEX_DEPLOY_KEY` (Production scope; copy
  from Convex dashboard → Settings → URL & Deploy Key)
- `VITE_CONVEX_URL` and `VITE_CONVEX_SITE_URL` are injected by
  `convex deploy --cmd` — do not set them manually on Vercel.
- `pnpm build` runs `convex codegen` itself before `vite build`, so even
  if the outer `convex deploy` ever changes behavior, the generated
  client is always present at bundle time.

## Gotchas

- **`convex/_generated/`** is gitignored. The frontend won't typecheck
  until `npx convex dev` (or `convex codegen`) has run at least once and
  produced these files. `pnpm build` runs codegen automatically.
- **Schema field removals need a migration.** Convex push will fail if
  any row carries a field the validator no longer declares. Pattern:
  re-add the field as `v.optional(...)`, ship, run a `ctx.db.replace`
  migration that rewrites docs without the field, then drop the optional
  from `schema.ts`. See `convex/migrations.ts:stripResolutionSource` for
  the template.
- **Theme-init script** in `__root.tsx` adds `class="dark"` to `<html>`
  before React hydrates and defaults to dark mode.
  `<html suppressHydrationWarning>` is required to silence the resulting
  mismatch warning — don't remove it.
- **Chunk-error recovery**: `__root.tsx` ships a tiny script that listens
  for `vite:preloadError`, `window.error`, and `unhandledrejection`. If
  a code-split chunk fails to load (typical right after a Vercel deploy
  that hashed new chunk names), it hard-reloads the page once
  (debounced via `sessionStorage` to avoid loops). The error boundary
  also auto-reloads on these errors and shows a friendly "New version is
  live" panel. **Don't disable** unless you've got something better.
- **Convex during SSR**: hooks return `undefined` server-side. Plan for
  it — every page renders a skeleton or empty state when queries are
  loading. Don't read `useQuery(...)` and assume non-null.
- **Chart history**: `priceTicks` is empty until trades happen. The
  detail page falls back to a deterministic synthetic line generated by
  `trail(yesPrice)`. Once real ticks exist, the real series renders.
- **TanStack Router `Link search`**: must match the route's
  `validateSearch` shape. The `q` param on `/tickets` is optional —
  pass `undefined` not `""` to keep the URL clean.
- **No top-up UI**: `api.wallet.topUp` and `reset` are gone. Use
  `admin.adjustBalance` from the admin user drawer if you need to give
  someone shekels.
- **Public profile fetch**: `users.publicProfile`, `publicPositions`,
  `publicTrades` all require the `users.by_handle` index. If you ever
  drop the index, those queries throw at runtime.
- **iOS input zoom**: `<Input>` and `<Textarea>` use `text-base md:text-sm`
  so mobile Safari doesn't auto-zoom on focus. Don't downgrade either.
- **No email/SMS integration**: don't add notification preference
  toggles that imply delivery channels that aren't wired up.
